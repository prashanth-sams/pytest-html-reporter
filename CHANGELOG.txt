Change Log
0.3.4 (30/08/2026)
-------------------
- Added the html_report ini key, so the report location can be set in pytest.ini without going through addopts (#228)
- The report path now expands strftime placeholders, e.g. --html-report=./reports/%Y%m%d/report_%H%M.html, giving each run a folder or filename of its own without a conftest hook (#228)
- Placeholders are expanded once while the run is configured, so an xdist run and a run that crosses a minute boundary still write a single report; a % that is not a placeholder is left alone, and %% writes a literal one

0.3.3 (30/08/2026)
-------------------
- Added captured logs per test: stdout, stderr and logging output from setup, call and teardown are kept against the test that produced them and opened from a new Logs column in Test Metrics
- Captured output is held outside the table, so it is not swept into the metrics search box or the CSV, Excel and print exports
- A retried test shows the output of the attempt that was reported, not the attempts it superseded, and captured output survives an xdist run intact
- The report now says why the Logs column is empty when a run uses -s / --capture=no (pytest captures no stdout or stderr at all then, only logging output), and the Environment panel states what the run kept and from which log level
- The bundled pytest.ini now uses --capture=tee-sys instead of -s, so the demo run still streams output live and its captured output reaches the report
- Added --report-logs / the report_logs ini key (all, failed or none) to narrow whose output is kept
- Added --report-log-limit / the report_log_limit ini key to cap the characters kept per test (default 10000, 0 keeps everything); a trimmed test keeps the end of its output, cut to a whole line
- Fixed reruns being counted as extra failures when the retry count comes from @pytest.mark.flaky(reruns=n) rather than --reruns (#212)
- Reruns are now worked out by collapsing the attempts of a test into one record, so --reruns, the reruns ini key, the flaky marker, a marker that disagrees with --reruns, and --only-rerun all report the same totals pytest itself prints
- A test that passes on a retry is reported as passed, with the attempts it took as its rerun count
- A retry that attaches no screenshot of its own keeps the screenshot of the attempt it replaced

0.3.2 (30/08/2026)
-------------------
- Added pytest-xdist support: a parallel run now produces one report instead of one per worker, with every test, suite and total in it, and a single build in Archives (#178, #55)
- Tests in a parallel report are listed in collection order, so it reads the same as a serial run whatever --dist mode is used
- Fixed --reruns being silently ignored under xdist (workers are started with an empty argv, so the value is now read from the pytest config)
- Fixed screenshots: attach() raised AttributeError instead of saving the image, and each screenshot is now written once, under a name that cannot collide between workers
- Fixed run times over a minute being reported as seconds
- Report titles are now capped at 20 characters with the cut tail faded out, and the full title kept as the heading's tooltip
- Added an Environment overlay to the dashboard: host, platform, python and pytest versions, active plugins, invocation arguments, rootdir and generation time
- Added --environment / the environment ini key to name the environment under test; it shows as a badge beside the report title, capped at 10 characters with the cut tail faded out and the full name in the Environment panel
- Added --build-info KEY=VALUE / the build_info ini key for arbitrary run details (branch, commit, CI job) in the Environment panel

0.3.1 (30/08/2026)
-------------------
- Redesigned the dashboard, suite highlights and test metrics tables with a cleaner, consistent layout
- Reworked the Archives view; fixed the archive build count (was silently dropped by a typo) and chart sizing

- Charts now re-fit on window resize instead of reloading the page, so the open tab, scroll position and table filters are preserved
- Fixed responsive alignment issues across the dashboard, side navigation and tables
